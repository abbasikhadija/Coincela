# Design system

Progressive disclosure, task-focused interaction and calm minimalism govern the interface. Milestone 1 adds simple registration/sign-in, a protected workspace and basic settings. Overview confirms account readiness without fabricated amounts or charts. Primary navigation remains Overview, Import, Review Payments, Invoices, Activity; through M4, all except Activity support their current workflows. Workspace settings and sign out stay separate from this task flow.

Tokens: paper #f6f7f3, surface #ffffff, ink #222c29, muted text #56645e, emerald #24644e, line #d8dfd9, input border #7b8c80, error #a43232. Color never substitutes for status text. Inter is bundled locally via @fontsource/inter. Type scale: 12/14/16/22/28/32 px; line height 1.6 body, 1.2–1.35 headings. Amount style uses tabular numerals. Spacing uses 4px multiples: 4/8/12/16/20/24/28/32/40/48/64.

Buttons and inputs have 44px minimum height. Components include Button, labeled Field, Panel and Connectivity. Inputs support aria-invalid; future forms must add described error text. All interactive elements have a 3px emerald focus outline with 4px offset. Native links/buttons and semantic header/nav/main/footer, skip link and polite status announcements form the accessibility foundation. Text remains readable without relying on color or animation.

Desktop content is capped at 1200px, with a 200px navigation column and focused content panel. Below 768px navigation becomes a horizontally scrollable row and content becomes sequential. Tailwind's standard breakpoints remain available; the shell has one deliberate mobile breakpoint. No gradients, decorative charts, oversized cards or attention-grabbing animations.

Later payment review must use master-detail on desktop and sequential mobile review. All important amounts, customer, reference, discrepancies and allocation consequences remain visible before confirmation. Suggestions must be visually distinct from confirmed allocations. Target WCAG 2.2 AA; current keyboard/responsive checks do not constitute a complete conformance audit.

Auth forms use native labels, correct autocomplete, required fields and length limits. Registration asks only email, password and business/workspace name; GBP is fixed. Visible password guidance is associated with its field. Submission disables the primary button and reports busy state. Validation errors use role=alert; expiry/restoration and saved settings use status announcements. Network failures offer recovery and logout failure never falsely claims revocation. Settings exposes only workspace name, fixed currency and account email.

Milestone 2 turns Import and Invoices into functional views. Overview's primary action is Import your invoices. Import Center uses one type selector, a sample link, native labeled file input and one upload action. Payment selection reveals the named-account selector and an optional Add account disclosure. File limits/date/currency guidance remain visible. Validation explains that zero financial records were inserted and shows row/field errors; completed imports show inserted/skipped/review counts and a next action. Review suggestions are explicitly unavailable until Milestone 3.

History and record tables use column headers, scroll containers and pagination rather than overcrowding the shell. Payment browsing is contextual via Import, not another primary nav item. Duplicate warnings use text, not color alone. Native keyboard file input and form submission, disabled busy actions, status announcements and mobile viewport checks remain part of verification.

Milestone 3 makes Review Payments functional. Desktop shows incoming payments (25 per page) beside the selected detail; mobile shows one step at a time with Back to payments. Payment selection is preserved in the hash-route query on refresh. List items display current unallocated amount, payer/description, date, duplicate indicator and snapshot review state. Only one item uses the selected style.

The detail shows original/unallocated payment, payer/reference/description/date, candidate customer/invoice, original/outstanding/suggested amounts, supporting evidence and warnings. Suggestions carry an Unconfirmed label; multiple plausible invoices display Ambiguous clearly. No-match is a valid explanation. Stale results hide old candidates and provide regeneration. Native buttons, selected-state ARIA, focused detail heading, status/error feedback and text warnings support keyboard/screen-reader access. Reject only changes review status; no confirmation action is displayed. Five candidates show initially, with progressive reveal for additional candidates. Screenshot review and responsive/keyboard browser checks do not claim full WCAG conformance.

M4 introduces a separate focused allocation form. Starting from a suggestion preserves visible evidence, ambiguity and warnings; manual selection/search/pagination supports splits and unmatched payments. Original task controls hide during allocation review. Show original/available payment, payer/reference/description, selected invoice/customer/total/outstanding, editable GBP amount, each invoice remainder, total allocation and payment remainder. A labeled native checkbox acknowledges the current draft and resets on edits. Confirmation stays disabled until all amounts are valid and acknowledged. Duplicate and reversal-availability warnings appear before submission.

Unknown responses keep the exact confirmed payload and offer Retry same confirmation after reload/reopening; editing is locked until the result is known. Successful receipts distinguish their recorded balances from current live balances, announce the outcome and refresh payment/list data. Native input borders, 44px targets, focus on the form/result heading, keyboard submission and desktop/mobile screenshots support review. Invoices and payments now show derived outstanding/unallocated columns. Full WCAG conformance is not claimed.
